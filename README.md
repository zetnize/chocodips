# Choco Dips

Локальный проект кофейни-десертной в Нальчике. Next.js App Router, React, TypeScript strict, Tailwind CSS. Анимации и взаимодействия реализованы без сторонних UI-библиотек.

## Запуск

Нужен Node.js 20.9+ (рекомендуется актуальная LTS).

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Для производственной проверки:

```powershell
npm run lint
npm run typecheck
npm run build
npm start
```

При запущенном локальном сервере в деморежиме `node scripts/check-api.mjs` проверяет API, валидацию, rate limit и публичные маршруты. Не запускайте эту проверку с настроенным боевым Telegram-каналом.

`next/font/google` загружает шрифты при сборке: машине сборки нужен доступ к Google Fonts.

## Настройка

Страница `/menu` оформлена как каталог: навигация по категориям вокруг логотипа, примечание, кнопки разделов, поиск и вертикальные карточки блюд. Сетка — 4 колонки от 1024 px и 2 колонки на меньших экранах. Кофе, напитки и сезонные позиции показаны текстовыми списками. Переход к категории из шапки сбрасывает поиск, чтобы нужный раздел оставался доступен.

- `src/data/site.ts`: настоящий телефон и ссылки Instagram/Telegram. До настройки иконки соцсетей отображаются без неработающих ссылок; телефон скрыт.
- `src/data/menu.ts`: начальные данные для первого запуска. Дальнейшие изменения меню сохраняются через `/admin` в SQLite.
- `public/images/`: локальные изображения; названия совпадают с ТЗ. Не заданные фотографии блюд отображаются на тёплой подложке. Сгенерированные изображения иллюстрируют атмосферу и не являются фото реальных блюд или помещения.
- `.env.local`: `NEXT_PUBLIC_SITE_URL` — полный production URL без завершающего слеша; `NEXT_PUBLIC_ROUTE_URL` — ссылка на маршрут.
- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`: задаются вместе, только на сервере. Не коммитьте секреты. Без обоих значений API отвечает `{ ok: true, demo: true }`, интерфейс явно сообщает о деморежиме. Частично заполненная конфигурация считается ошибкой.
- `src/app/privacy/page.tsx`: утвердить текст, добавить оператора персональных данных, реквизиты, контакты и условия обработки до публичного запуска.

## Хостинг

Проект использует Next.js и SQLite. Для текущей версии нужен Node.js 24 и постоянный диск. Настройки окружения и хранения описаны в разделе администрирования ниже.

## Проверка вручную

1. Главная: видео-интро по центру, однократное воспроизведение на скорости 1,4× (около 4,3 секунды), затем сдвиг влево, кнопка меню и фотографии блюд справа. На телефоне блоки располагаются вертикально. Исходный ролик — `public/videos/choco-dips-intro.mp4`.
2. `/menu#coffee`: переход к кофе, активная категория, поиск по составу и названию (включая ё/е), пустой результат, карточка и её закрытие.
3. Видео: воспроизведение без кнопок паузы и пропуска; волновой индикатор под видео исчезает после его окончания. Ручной запуск при блокировке autoplay; статичный логотип и доступ к меню при ошибке видео. Фотографии первого экрана ведут в категории меню.
4. Бронь в подвале: обязательные поля, маска, согласие, отправка в деморежиме.
5. Мобильная навигация: Esc, переходы, блокировка прокрутки и фокуса фона.
6. Ширины 390, 768, 1024, 1440 px; режим reduced-motion.

## Ограничения

В API ограничены размер тела и число запросов на IP. In-memory rate limit действует в пределах одной серверной инстанции; для публичного трафика замените его общим Redis/Upstash. Телефон, социальные ссылки, данные оператора и меню требуют подтверждения владельцем. Бронь подтверждается сотрудником по телефону. Фактическая доставка через Telegram проверяется только с настроенными реквизитами.

## Администрирование меню

Откройте `/admin`. В настройках окружения хостинга задайте `ADMIN_LOGIN` (3–80 символов: латинские буквы, цифры, `_`, `-`) и `ADMIN_PASSWORD` (12–128 символов), затем перезапустите приложение. Для локальной разработки используйте `.env.local`. Переменные доступны только серверу. При смене логина или пароля прежние сессии перестают действовать.

В панели можно менять категории, группы, блюда, цены, размеры, состав, аллергены, отметки, фотографии, добавки, порядок и видимость. Изменения публикуются кнопкой «Сохранить изменения». Сезонный баннер использует выбранное в редакторе блюдо.

Нужен Node.js 24 и сервер с постоянным диском. SQLite и загруженные фотографии хранятся в `data/`, которая исключена из Git. Можно задать абсолютный путь через `CHOCO_DATA_DIRECTORY`. При переносе сохраните всю эту папку, включая `uploads/`. Для согласованной резервной копии остановите приложение перед копированием. Хостинг с временной файловой системой (включая стандартный Vercel) потребует замены хранилища на внешнюю базу и объектное хранилище.
